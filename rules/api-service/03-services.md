# Business services and state transitions

Evidence: `sales_service.go`, `workflow_service.go`, `tenant_onboarding_service.go`, `overview_service.go`, `ai_agent_service.go` in `internal/core/service`.

| Rule ID | Origin | Requirement | Verification |
| --- | --- | --- | --- |
| SVC-001 | E | Services MUST own use-case orchestration, actor/resource authorization, business validation, calculations and transition decisions. They MUST NOT construct SQL, call DB/cache drivers, bind HTTP requests or write HTTP responses. | S imports/AST; R use-case logic |
| SVC-002 | P | Service constructors MUST receive the narrow behavior interfaces they consume. Production construction MUST NOT require a concrete repository/client just because Fx can provide it. Current repository-owned interfaces remain allowed pending the ports-location decision. | S constructor/field types; T fakes/Fx |
| SVC-003 | E | Business operations that can fail MUST return the shared `*errors.Error` type. Constructor/lifecycle configuration failures MAY return ordinary `error` at startup boundaries; pure value functions need no artificial error return. | S signatures; R classification |
| SVC-004 | O | Tenant-scoped services MUST require trusted actor and tenant scope, recheck current membership/status and authorize the requested action/resource. A header, cached tenant, valid JWT or internal service token alone MUST NOT grant business permission. | T wrong actor/tenant, revoked/inactive cases; R all entry points |
| SVC-005 | O | Services MUST choose the use-case transaction scope through repository transaction interfaces; repositories implement BEGIN/COMMIT/ROLLBACK and locks. Every write/audit that must succeed together MUST use the same transaction-scoped persistence instance. | R call graph; T rollback/failure injection |
| SVC-006 | O | Concurrent state-changing commands MUST have an explicit conflict/replay strategy. Versioned sales/workflow mutations MUST validate expected versions and reject stale changes; transition rules MUST be explicit and terminal states protected. | T stale/racing commands; R state table |
| SVC-007 | O | Commands declaring idempotency MUST persist key scope and request fingerprint with the result atomically. Reusing the same key/payload MUST replay the defined result; changed payload MUST conflict. A random new key on retry is not equivalent. | T replay, mismatch and concurrent duplicate |
| SVC-008 | E | Go MUST own business authorization and sending decisions; AI output is untrusted candidate data. A generated draft MUST NOT authorize confirmation/send or bypass catalog/current-state checks. New Python AI execution MUST stay behind its service contract. Legacy Go generation is recorded debt, not permission to expand provider orchestration. | R ownership; T unsafe candidate/transition |
| SVC-009 | O | Monetary calculations MUST use decimal values and explicit range/precision rules. Missing price MUST remain distinguishable from zero where the domain supports incomplete drafts. Invalid/overflow/negative values MUST be rejected according to the use case. | S float arithmetic scan; T price/rounding boundaries |
| SVC-010 | P | Services MUST NOT hold database locks open across external provider/channel calls. Durable intent/reconciliation requires a separate approved design before side effects are added; no best-effort rollback loop may be assumed atomic. | R transaction/external-call trace; T fault cases |

Business state is currently primarily changed by application-service logic; the draft does not mandate rich aggregates, one service per table, CQRS or event sourcing. A service MAY call another service through a narrow interface when this preserves authorization and transaction guarantees; it MUST NOT recurse through HTTP to its own API as a layer bypass.
