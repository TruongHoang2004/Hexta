## 1. Overview & Goal
Resolve architectural boundary violations where HTTP controllers in `services/api` previously imported infrastructure clients (`*gorm.DB`, SQL drivers) directly or performed database queries inline.
Enforce strict compliance with Hexta's 5-layer Go architecture:
1. `cmd/`: Application entrypoints.
2. `internal/present/http/controller/`: HTTP handlers and request validation. No direct database or cache dependencies; interact solely via core services.
3. `internal/core/service/`: Business logic and orchestration. Transport-agnostic.
4. `internal/repository/`: Data persistence and caching interfaces/implementations.
5. `internal/infrastructure/`: Low-level database and Redis drivers.

## 2. Scope of Changes
1. **Health Controller Refactoring & DTO Standardization**:
   - Ensure `HealthController` delegates all health verification to `IHealthService`.
   - Introduce `HealthCheckResponse` DTO in `services/api/internal/present/http/dto/health_dto.go` conforming to `response.Response[T]`.
   - Update Swagger documentation annotations to standard response format.
2. **Comprehensive Unit Testing**:
   - Add unit test suite `services/api/internal/present/http/controller/health_controller_test.go` with mock/stub service verification.
   - Test both healthy (200 OK) and degraded/down (503 Service Unavailable) responses.
3. **Verification**:
   - Run `go vet ./services/api/... ./packages/shared/...`
   - Run `go test -v -race ./services/api/... ./packages/shared/...`
   - Verify zero architectural violations reported by `.agents/scripts/audit_codebase.py`.

## 3. Step-by-Step Execution Plan

### Step 3.1: Define Health DTO
Create `services/api/internal/present/http/dto/health_dto.go`:
```go
package dto

type HealthCheckResponse struct {
    Status  string            `json:"status"`
    Details map[string]string `json:"details"`
}
```

### Step 3.2: Align Health Controller & Swagger Annotations
Update `services/api/internal/present/http/controller/health_controller.go`:
- Use `dto.HealthCheckResponse` inside `response.NewSuccessResponse`.
- Update Swagger `@Success` and `@Failure` annotations to `response.Response[dto.HealthCheckResponse]`.

### Step 3.3: Add Controller Unit Tests
Create `services/api/internal/present/http/controller/health_controller_test.go`:
- Test healthy status (`200 OK`).
- Test degraded/unhealthy status (`503 Service Unavailable`).
- Validate response payload structure and JSON encoding.
