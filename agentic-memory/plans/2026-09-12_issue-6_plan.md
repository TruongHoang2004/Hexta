# Implementation Plan: Reconcile Auth Token Storage, Synchronize JWT Claims & Enforce English Language Rule (Issue #6)

- **Date**: 2026-09-12
- **Issue**: [#6 - fix(web): reconcile auth token storage, synchronize JWT claims, and enforce English language rule](https://github.com/TruongHoang2004/Hexta/issues/6)
- **Branch**: `task/issue-6-fix-web-reconcile-auth-token-storage-syn`

---

## 1. Overview & Goal

During end-to-end authentication testing across `apps/web` and `services/api`, three key problems were identified:
1. **Storage Desynchronization**: OAuth callback (`apps/web/app/auth/callback/page.tsx`) stores `auth_token` into Cookies, whereas the dashboard workspace (`apps/web/app/(dashboard)/tenant/page.tsx`) checks `localStorage.getItem("auth_token")`. As a result, users logging in via Google OAuth are bounced back to `/login` despite a valid token.
2. **JWT Claims Mismatch**: The Zustand store `useAuthStore` attempts to extract `payload.sub` and `payload.email`, but backend JWT claims only include `user_id` and omit `email`. The user store is therefore populated with `{ id: "", email: "" }`.
3. **Language Rule Violation**: Several pages in `apps/web` (`login`, `register`, `callback`, landing `page.tsx`, and `auth-nav.tsx`) contain hardcoded Vietnamese strings, violating the mandatory English rule in `GEMINI.md`.
4. **Missing Server-Side Route Protection**: Protected routes under `/(dashboard)/*` lack a Next.js `middleware.ts`, causing flashes of unauthenticated content and relying on client-side `useEffect` redirects.

### Objectives
- Standardize all client-side token storage on Cookies via `DefaultBrowserStorage` from `@ubi/sdk`.
- Enrich backend JWT claims with `email` and ensure `sub` (Subject) is populated.
- Update `useAuthStore` to robustly extract `id` (`payload.sub || payload.user_id`) and `email` (`payload.email`).
- Translate all Vietnamese UI strings to clean, idiomatic English.
- Implement Next.js `middleware.ts` for route protection on `/tenant/:path*`, `/login`, and `/register`.
- Add `<Suspense>` boundary around `useSearchParams()` in `apps/web/app/auth/callback/page.tsx`.
- Verify build and tests across `services/api` and `apps/web`.

## 2. Current State Analysis

### 2.1 Storage Mechanism
- `packages/sdk/src/index.ts`: Defines `DefaultBrowserStorage` which uses `Cookies.get/set/remove("auth_token")`.
- `apps/web/app/auth/callback/page.tsx`: Uses `Cookies.set("auth_token", token, ...)`.
- `apps/web/app/(dashboard)/tenant/page.tsx`: Uses `localStorage.getItem("auth_token")` (Bug: does not match Cookie storage).

### 2.2 JWT Claims
- `services/api/internal/core/service/auth_service.go`:
  ```go
  type JWTClaims struct {
      SessionID int64  `json:"session_id"`
      UserID    string `json:"user_id"`
      jwt.RegisteredClaims
  }
  ```
  `RegisteredClaims.Subject` is set to `userID`, but `Email` is missing from `JWTClaims`.
- `apps/web/store/useAuthStore.ts`:
  Parses `payload.sub` and `payload.email`. Because `payload.email` is missing, `user.email` is empty.

### 2.3 UI Language
- Hardcoded Vietnamese strings found in:
  - `apps/web/app/(auth)/login/page.tsx`
  - `apps/web/app/(auth)/register/page.tsx`
  - `apps/web/app/auth/callback/page.tsx`
  - `apps/web/components/auth-nav.tsx`
  - `apps/web/app/page.tsx`

## 4. Risk Assessment & Edge Cases

| Risk / Edge Case | Impact | Mitigation Strategy |
| :--- | :--- | :--- |
| **Existing JWT tokens lack `email` claim** | Older tokens parsed by `useAuthStore` might have empty email | Default to `""` with fallback `payload.email || ""`. |
| **Next.js middleware performance overhead** | Added latency on static asset requests | Restrict matcher in `config` to `/tenant/:path*`, `/login`, `/register`. |
| **Hydration mismatch on client auth state** | React hydration warning | Synchronize store via `initialize()` in `useEffect` or client layout. |
