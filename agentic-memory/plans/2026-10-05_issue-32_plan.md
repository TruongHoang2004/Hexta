# Implementation Plan: Default Light Mode with Seamless Dark Mode Toggle Support

- **Issue**: [#32](https://github.com/TruongHoang2004/Hexta/issues/32)
- **Date**: 2026-10-05
- **Branch**: `task/issue-32-feat-ui-set-light-mode-as-default-theme-`
- **Scope**: Frontend UI package (`packages/ui`) and web application (`apps/web`)

---

## 1. Overview & Goal
The Hexta web platform currently relies on system preference media queries without an explicit light-first default or direct user theme toggle. The goal of this task is to establish **Light Mode as the default theme** across the web interface (prioritizing light mode on initial load), while fully preserving dark mode functionality through an accessible and responsive theme toggle mechanism.

### Key Objectives:
1. Provide reusable `ThemeProvider` and `ThemeToggle` components from `@hexta/ui`.
2. Configure `apps/web` with `defaultTheme="light"`, class-based theme switching (`.dark`), and hydration-safe rendering.
3. Place accessible theme toggles (Sun / Moon) in the public landing navigation, auth navbar, and tenant dashboard header.
4. Validate styling, contrast, build, and linting across the monorepo.

---

## 2. Technical Analysis & Architecture

### Theme Provider & Switching Logic
- Package `@hexta/ui` includes `next-themes` (`^0.4.6`).
- We encapsulate `NextThemesProvider` in `packages/ui/src/components/theme-provider.tsx` and export it along with `ThemeToggle`.
- In `apps/web/app/layout.tsx`, wrap the application in:
  ```tsx
  <ThemeProvider attribute="class" defaultTheme="light" enableSystem={false} disableTransitionOnChange>
    {children}
    <Toaster />
  </ThemeProvider>
  ```
- In `apps/web/app/globals.css`:
  - Define `:root` with light-mode CSS variables as the default theme.
  - Define `.dark` selector (instead of purely `@media (prefers-color-scheme: dark)`) so `next-themes` toggling directly activates dark mode styles.
  - Configure `@custom-variant dark (&:where(.dark, .dark *));` to ensure Tailwind utilities (`dark:...`) resolve properly.

### Component Styling & Contrast
- **Light Mode (Default)**:
  - Background: `#F8FAFC` (Slate-50)
  - Foreground: `#0F172A` (Slate-900)
  - Surface: `#FFFFFF`
  - Border: `#E2E8F0`
  - Text Muted: `#64748B`
- **Dark Mode**:
  - Background: `#020617`
  - Foreground: `#F8FAFC`
  - Surface: `#0E1526`
  - Border: `#1E293B`
  - Text Muted: `#94A3B8`

## 3. Step-by-Step Execution Plan

### Step 3.1: Export Theme Components from `packages/ui`
- Create `packages/ui/src/components/theme-provider.tsx` wrapping `next-themes`.
- Create `packages/ui/src/components/theme-toggle.tsx` with Sun/Moon transition icons and accessible click handler.
- Export both in `packages/ui/src/index.ts`.

### Step 3.2: Update `apps/web` Global Styling & Root Layout
- Update `apps/web/app/globals.css`:
  - Add Tailwind dark mode class variant configuration.
  - Explicitly define `:root` (light default) and `.dark` (dark mode) custom properties.
- Update `apps/web/app/layout.tsx`:
  - Wrap application inside `ThemeProvider` with `defaultTheme="light"` and `enableSystem={false}`.

### Step 3.3: Integrate Theme Toggle in `apps/web`
- In `apps/web/components/auth-nav.tsx`:
  - Include `<ThemeToggle />` beside user profile / action buttons.
- In `apps/web/app/(dashboard)/tenant/page.tsx`:
  - Add `<ThemeToggle />` to the workspace header next to tenant switcher.

### Step 3.4: Verification & Quality Assurance
- Run `pnpm run build` across monorepo to ensure TypeScript and Next.js compile without errors.
- Run `pnpm run lint` to confirm no linting regressions.
