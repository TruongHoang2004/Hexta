## 1. Overview & Goal
Implement the conversational AI Agent service and HTTP SSE handlers in Go connecting to Google Gemini API via official SDK, establishing schema-governed tool calling registry (`search_products`, `check_stock_availability`, `propose_order_draft`), Redis draft caching (30-min TTL), and Server-Sent Events (SSE) streaming endpoint.

### Core Invariants:
1. **Zero Direct DB Mutations**: The AI Agent MUST NEVER write directly to `orders` or database tables. All purchasing intent is captured as an Order Draft proposal.
2. **Strict Multi-Tenant Boundary**: Forcefully inject and validate `tenant_id` from JWT session context into all tool arguments. Prevent cross-tenant data leakage.
3. **Structured Event Stream**: Real-time SSE streaming emitting `token`, `tool_call`, `tool_result`, `draft_proposed`, and `done` events.
4. **Draft Cache with TTL**: Drafts stored under `hexta:draft:<tenant_id>:<draft_id>` in Redis with 30-minute expiration.

## 3. Step-by-Step Execution Plan

### Step 3.1: Infrastructure Layer (`gemini.IGeminiClient`)
- Define `IGeminiClient` interface and implementation wrapping Gemini API.
- Support `GenerateContent` and function calling declarations.

### Step 3.2: DTOs & Event Schemas (`dto.ai_dto.go`)
- Define `AIConverseRequest`, `ChatMessageDTO`, `OrderDraftDTO`, `DraftItemDTO`.
- Define `SSEEvent` types: `token`, `tool_call`, `tool_result`, `draft_proposed`, `done`, `error`.

### Step 3.3: Core Service Layer (`AIAgentService`)
- Implement `search_products`: query products and variants scoped by `tenant_id`.
- Implement `check_stock_availability`: query variant and inventory items scoped by `tenant_id`.
- Implement `propose_order_draft`: calculate totals with `decimal.Decimal`, generate unique draft UUID, store in Redis with 30m TTL, emit `draft_proposed` event.
- Implement `GetDraft`: retrieve and tenant-validate cached draft from Redis.
- Enforce zero direct DB mutations.

### Step 3.4: Controller & Router Layer (`AIController`)
- Implement `Converse` handler using Gin HTTP SSE (`text/event-stream`).
- Flush events iteratively to response writer.
- Implement `GetDraft` handler returning `response.Response[dto.OrderDraftDTO]`.
- Add Swagger annotations and update swagger specs.

### Step 3.5: Testing & Verification
- Unit test all tool executions, multi-tenant isolation, and SSE event emissions.
- Run `go test -race ./...` in `services/api`.
- Run `dev-review` and `dev-changelog`.
