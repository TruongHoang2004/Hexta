# Implementation Plan: Fix Unique Identifier Collision & Multi-Provider Linking (Issue #5)

- **Date**: 2026-09-12
- **Issue**: [#5 - fix(db): resolve unique identifier collision on OAuth login and enable multi-provider linking](https://github.com/TruongHoang2004/Hexta/issues/5)
- **Branch**: `task/issue-5-fix-db-resolve-unique-identifier-collisi`

---

## 1. Overview & Goal

Currently, the `identities` table in PostgreSQL defines a unique index solely on `identifier` (`idx_identities_identifier` on `identifier`).
When a user who initially registered via email/password (`provider: "local"`) subsequently signs in via Google OAuth (`provider: "google"`) using the same email address:
1. `GetCredentialByIdentifier(email, ProviderGoogle)` returns `nil`.
2. The system attempts to insert a new row `(user_id: <new-uuid>, provider: "google", identifier: email, password: "oauth2-dummy")`.
3. The database rejects this insertion with a PostgreSQL unique constraint violation (`idx_identities_identifier`).
4. Furthermore, generating a new `user_id` splits accounts for the same user, and storing `"oauth2-dummy"` as a password in plaintext violates security practices.

### Objectives
1. **Database Schema & Migrations**:
   - Drop the single-column unique index `idx_identities_identifier` on `(identifier)`.
   - Add a compound unique index `idx_identities_provider_identifier` on `(provider, identifier)`.
   - Make the `password` column nullable (`*string`) so OAuth-based identities do not require or store dummy plaintext passwords.
   - Generate and apply versioned Atlas migration (`migrations/api/`).
2. **Multi-Provider Identity & Account Linking**:
   - Extend `IIdentityRepository` to query existing identities across providers (e.g. `GetByIdentifier(ctx, identifier)` or `GetFirstByIdentifier(ctx, identifier)`).
   - In `AuthService.GoogleCallback`: If an identity for `(email, "google")` does not exist, check if an identity with the verified email already exists under another provider (e.g. `local`).
     - If found: Link the new Google identity to the existing `user_id`.
     - If not found: Generate a new `user_id` and create the Google identity.
     - Store `Password: nil` instead of `"oauth2-dummy"`.
   - In `AuthService.Login`: Safely check `identity.Password != nil` before calling `bcrypt.CompareHashAndPassword` to avoid nil-pointer dereferences when users without local passwords attempt local login.
3. **Testing & Verification**:
   - Add comprehensive unit/integration tests covering:
     - Register with local password.
     - Google OAuth login with the same email links to the existing `user_id`.
     - Subsequent Google OAuth login finds the linked identity.
     - Login with password continues working.
     - Attempts to login with password on an OAuth-only account (nil password) return 401 Unauthorized without panicking.
     - Duplicate identity under the same provider and identifier is rejected by the compound unique constraint.

## 2. Current State Analysis

### 2.1 Model: `services/api/internal/core/model/identities.go`
```go
type AuthIdentities struct {
	ID         int64     `gorm:"primaryKey;autoIncrement;column:id" json:"id"`
	UserID     string    `gorm:"column:user_id;not null;index" json:"user_id"`
	Provider   Provider  `gorm:"column:provider;type:varchar(50);not null" json:"provider"`
	Identifier string    `gorm:"column:identifier;type:varchar(255);not null;uniqueIndex" json:"identifier"`
	Password   string    `gorm:"column:password;type:varchar(255);not null" json:"password"`
	CreatedAt  time.Time `gorm:"column:created_at;autoCreateTime" json:"created_at"`
	UpdatedAt  time.Time `gorm:"column:updated_at;autoUpdateTime" json:"updated_at"`
}
```
- `Identifier` has `uniqueIndex` tag (generates `idx_identities_identifier`).
- `Password` is `string` with `not null`.

### 2.2 Repository: `services/api/internal/repository/identify_repository.go`
- Only exposes `GetCredentialByIdentifier(ctx, identifier, provider)` and `CreateIdentity(ctx, authIdentity)`.
- Cannot query across providers for a given identifier (email).

### 2.3 Service: `services/api/internal/core/service/auth_service.go`
- `Register`: generates `uuid.New().String()`, sets `Password: string(hashedPassword)`.
- `Login`: calls `bcrypt.CompareHashAndPassword([]byte(identity.Password), []byte(password))` directly without nil check.
- `GoogleCallback`:
  ```go
  identity, dbErr := s.identityRepo.GetCredentialByIdentifier(ctx, userInfo.Email, model.ProviderGoogle)
  if dbErr != nil { return nil, dbErr }
  if identity == nil {
      identity = &model.AuthIdentities{
          UserID:     uuid.New().String(),
          Provider:   model.ProviderGoogle,
          Identifier: userInfo.Email,
          Password:   "oauth2-dummy",
      }
      identity, dbErr = s.identityRepo.CreateIdentity(ctx, identity)
      ...
  }
  ```

### 2.4 Migrations: `migrations/api/`
- Initial migration `20260220100303_init.sql` created `CREATE UNIQUE INDEX "idx_identities_identifier" ON "public"."identities" ("identifier");`.
- `atlas.hcl` config path had a slight discrepancy (`../../service/api` vs `../../services/api`).

## 3. Task Breakdown (Step-by-Step)

### Step 3.1: Update Database Model
- **File**: `services/api/internal/core/model/identities.go`
  - Update `Provider` tag: `uniqueIndex:idx_identities_provider_identifier`
  - Update `Identifier` tag: `uniqueIndex:idx_identities_provider_identifier` (remove single-column `uniqueIndex`)
  - Change `Password` from `string` with `not null` to `*string` with nullable tag: `gorm:"column:password;type:varchar(255)" json:"password,omitempty"`.

### Step 3.2: Update Repository
- **File**: `services/api/internal/repository/identify_repository.go`
  - Add `GetFirstByIdentifier(ctx context.Context, identifier string) (*model.AuthIdentities, *errors.Error)` to `IIdentityRepository` and `IdentityRepository`.
  - Also ensure `ListByIdentifiers` or `GetCredentialByIdentifier` handles nullable passwords smoothly.

### Step 3.3: Update Authentication Service
- **File**: `services/api/internal/core/service/auth_service.go`
  - `Register`: Convert `string(hashedPassword)` to `*string` for `Password`.
  - `Login`: Guard password verification against `nil` password (e.g. if an OAuth-only user attempts password login, return `errors.ErrUnauthorized(ctx).SetMessage("Invalid email or password")`).
  - `GoogleCallback`:
    - First check `s.identityRepo.GetCredentialByIdentifier(ctx, userInfo.Email, model.ProviderGoogle)`.
    - If `identity == nil`:
      - Query `s.identityRepo.GetFirstByIdentifier(ctx, userInfo.Email)`.
      - If existing identity found: use `userID = existing.UserID` (link accounts).
      - If no existing identity found: generate new `userID = uuid.New().String()`.
      - Create Google identity with `UserID: userID`, `Provider: model.ProviderGoogle`, `Identifier: userInfo.Email`, `Password: nil`.

  3. Alters `password` column to drop `NOT NULL` constraint (`ALTER TABLE "identities" ALTER COLUMN "password" DROP NOT NULL;`).
- Apply migration and verify status.

### Step 3.5: Unit & Integration Testing

## 4. Risk Assessment & Edge Cases

| Risk / Edge Case | Impact | Mitigation Strategy |
| :--- | :--- | :--- |
| **Existing database has duplicate `(provider, identifier)` rows** | Migration failure when creating compound unique index | Database previously had unique constraint on `identifier`, so duplicates cannot exist. |
| **Nil pointer dereference when querying `Password` on OAuth identity** | Panic / 500 error in `Login` or serializer | `AuthIdentities.Password` is `*string`. `Login` explicitly checks `if identity.Password == nil`. JSON tag includes `omitempty`. |
| **Race condition during concurrent OAuth login and local registration** | Duplicate `(provider, identifier)` error | Compound unique constraint in Postgres guarantees consistency; database error returns standard conflict error. |
| **Account hijacking via unverified email** | Security risk if an attacker registers local with a target's email | Google OAuth provides verified email addresses (`email_verified = true`). Linking verified OAuth identity to existing account is safe. |
